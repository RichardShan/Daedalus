# 规范初始化

从真实代码库生成 `.daedalus/spec/` 编码指南。一个 Agent 完成全部流程：分析仓库 → 选定规范边界 → 编写文档 → 验证结果。

## 工作流

1. 检查 `.daedalus/spec/` 是否存在，审视当前内容
2. 用可用工具分析仓库架构（语言工具、MCP 集成、直接读源码）
3. 按实际代码结构拆分规范单元（包/层），不要人为制造粒度
4. 用项目中的真实模式、文件路径、代码示例和反模式填充规范文件
5. 验证最终规范内部一致且无模板占位符

## 原则

- 模板是起点不是终点 — 不适用的就删、该拆的拆、该合的合
- 规则要有证据 — 每条重要建议都指向真实的文件或反复出现的模式
- 不写空泛建议 — 「注意代码质量」不是规范，「Error handler 必须包含 requestId，参见 `src/xxx.java:42`」才是
- 不留占位文本 — 没有内容的章节删掉

## 完成标准

- [ ] `.daedalus/spec/` 描述的是项目当前状态
- [ ] 每个相关的包/层有实操编码指南和真实示例
- [ ] 不适用的模板章节已删除
- [ ] `index.md` 与最终的规范文件集一致
- [ ] 无占位文本残留
