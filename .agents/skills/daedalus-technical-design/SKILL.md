# 技术设计

## 步骤

1. **摸底现状** — 读现有代码的边界、数据流和约束。理解「为什么是这样」而非只看「是什么」。
2. **选定方案** — 在满足需求的前提下选最小改动方案。有多个选择时列出权衡。
3. **定义接口** — 模块职责划分、输入输出类型、状态变化和失败处理。
4. **评估影响** — 改动涉及哪些模块？有没有上下游需要联动？是否存在破坏性变更？
5. **明确验证方式** — 怎么知道方案是对的？测试策略、验证命令、回滚策略。

## 输出格式

```markdown
## 方案概述
<一句话描述改动策略>

## 模块职责
| 模块 | 职责 | 改动类型 |
|------|------|----------|
| ... | ... | 新增/修改/无 |

## 接口契约
- 输入: ...
- 输出: ...
- 异常: ...

## 影响范围
- 直接影响: ...
- 间接影响: ...

## 备选方案（如有）
| 方案 | 优势 | 劣势 | 不选原因 |
|------|------|------|----------|

## 验证策略
- [ ] ...

## 回滚策略
- ...
```

## 原则

- 优先复用现有抽象 — 新增抽象需要说明为什么现有的不够用
- 最小改动 — 能改一行解决的不改十行
- 可逆性 — 优先选择容易回滚的方案
- 不留模糊地带 — 接口、异常处理、并发行为都要明确
