# 增量实现

## 原则

1. **保护现有工作** — 只修改当前任务需要的文件，不动无关代码。
2. **小步前进** — 每完成一个逻辑单元就局部验证，不要等全部写完再检查。
3. **遵循现有模式** — 先看周围代码怎么写，用同样的风格和抽象。
4. **接口清晰** — 命名一致、类型明确、错误信息包含上下文。
5. **不过度工程** — 只做需求要求的事。可扩展性在需求文档里没提就不加。
6. **安全底线** — 不把密钥、令牌或机器路径写入源码。

## 验证

改动完成后：

```bash
# 按项目配置执行可用的验证
lint / checkstyle
typecheck / compile
test                 # 仅在需求要求或改动涉及核心逻辑时
```
