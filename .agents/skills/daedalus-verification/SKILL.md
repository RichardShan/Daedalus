# 测试与验收

## 步骤

1. **匹配验证强度与风险** — 核心逻辑改动需要测试覆盖，配置调整只需编译通过。
2. **验证主要路径** — 正常输入 → 预期输出。
3. **验证边界条件** — 空值、零值、极端数量、并发场景。
4. **验证失败路径** — 错误输入、网络超时、资源不足。
5. **区分结论层次**：
   - ✅ 已验证 — 有测试/命令输出证明
   - ⚠️ 未验证 — 逻辑上应该没问题但没有直接证据
   - 🚫 受限 — 需要特定环境、数据或权限才能验证

## 交付摘要

```markdown
## 改动摘要
- ...

## 验证结果
| 检查项 | 结果 | 证据 |
|--------|------|------|
| 编译/类型检查 | ✅ | `npm run build` 输出 |
| Lint | ✅ | 无新增 warning |
| 单元测试 | ✅ | 12/12 passed |
| 手动验证 | ⚠️ | 需要 staging 环境 |

## 剩余风险
- ...
```

## 原则

- 不把推测描述成已验证事实
- 完成声明必须附带验证证据
- 「我检查了代码逻辑没问题」不算验证 — 至少跑一个命令
