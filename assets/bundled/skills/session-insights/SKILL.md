# 会话洞察

能力型 skill，不是固定流程。找到信息后根据当下对话判断怎么用。

## 什么时候该用

判断标准：「一个资深同事会不会问：我们之前不是讨论过这个吗？」

- **避免重复讨论** — 开始的任务涉及以前碰过的领域，先查查有没有已有决策
- **似曾相识的 bug** — 当前 bug 模式像之前修过的，拉出旧对话能省一整轮调试
- **跨会话继续** — 用户隔了一段时间回来说「继续上次的」
- **决策检索** — 用户说「我们之前定的 X」，但决策在旧对话里不在文档中
- **模式识别** — 用户问「我是不是每次都踩这个坑」

以上都不符合的话，别翻历史。

## 什么时候不该用

- 上下文已在当前对话、`git log` 或打开的文件中
- 用户问的是代码事实而非对话事实 — 直接读代码更快更准
- 子代理已收到完整的上下文注入
- 用户明确说「别翻历史」

## 怎么搜索

1. **对话记录** — `agent-transcripts/` 中的历史对话日志
2. **Git 历史** — `git log --all --oneline --grep="<keyword>"`
3. **规范文件** — `.daedalus/spec/` 中可能已沉淀的决策
4. **阶段产物** — `.daedalus/artifacts/` 中历史输出

## 找到后怎么用

- **直接引用** — 过去对话能回答当前问题时，引用并注明来源
- **更新文档** — 发现重要决策没被记录，提议更新需求或设计文档
- **沉淀规范** — 发现项目级惯例或注意事项，调用 standards-capture 来更新
- **吸收消化** — 很多时候最好的做法是理解了就好，不需要写什么

没有固定输出目标。强行把每次检索都写入文件只会制造噪音。

## 触发短语

- 「上次怎么解的」 / "how did we solve X last time"
- 「之前讨论过吗」 / "have we discussed this before"
- 「之前决定了什么」 / "what was the decision on X"
- 「继续上次的」 / "where were we"
- 「我每次都踩这个坑吗」 / "do I keep making the same mistake"
