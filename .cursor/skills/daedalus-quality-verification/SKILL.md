# 代码质量检查

## 步骤

### 1. 获取变更

```bash
git diff --name-only HEAD
git status
```

### 2. 读取规范

读取 `.daedalus/spec/` 中与变更模块相关的 index.md，跟踪到具体指南文件。

### 3. 运行工具检查

执行项目的 lint、类型检查和测试命令。失败则先修复再继续。

### 4. 逐维度审查

#### 代码质量
- [ ] Lint / 类型检查通过？
- [ ] 无遗留的 debug 日志？
- [ ] 无被压制的告警或类型安全绕过？

#### 测试覆盖
- [ ] 新函数 → 有单元测试？
- [ ] Bug 修复 → 有回归测试？
- [ ] 行为变更 → 现有测试已更新？

#### 安全性
- [ ] 无硬编码密钥、令牌？
- [ ] 用户输入有校验和转义？
- [ ] 异常信息不泄露内部细节？

#### 规范同步
- [ ] `.daedalus/spec/` 需要更新吗？

### 5. 跨层检查（改动跨 3+ 层时）

#### 数据流
- [ ] 读取链路：存储 → 服务 → API → UI 追踪正确？
- [ ] 写入链路：UI → API → 服务 → 存储 追踪正确？
- [ ] 层间类型/契约传递正确？
- [ ] 错误正确传播到调用方？

#### 代码复用
- [ ] 创建新工具类前搜索过已有的？
- [ ] 2+ 处定义相同值 → 提取为常量？

#### 一致性
- [ ] 同层中使用同一概念的地方是否一致？

### 6. 修复并重跑

发现问题直接修复，重跑工具检查确认。
